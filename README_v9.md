## 🎯 核心改進

### v9.0 相對於 v8.2 的重大升級

#### 1. **多目標優化（最重要）**
**問題**：v8.2 只優化夏普值，導致找到的策略可能胃納量不足

**解決方案**：
```python
# v8.2: 單目標
fitness = sharpe_ratio

# v9.0: 多目標綜合適應度
综合适应度 = (
    sharpe_score × 50% +      # 夏普值權重
    capacity_score × 30% +     # 胃納量權重（新增）
    return_score × 15% +       # 年化報酬權重
    drawdown_score × 5%        # 回撤懲罰權重
)

# 硬約束
if capacity < 250萬:  綜合適應度 × 0.3  # 嚴重懲罰
if drawdown > 30%:    綜合適應度 × 0.5  # 回撤懲罰
```

**效果**：
- ✅ 確保找到的策略**同時滿足**：夏普值 >= 4.0 **且** 胃納量 >= 500萬
- ✅ 避免「高夏普低胃納量」的不可交易策略
- ✅ 同時優化報酬率和控制回撤

#### 2. **NSGA-II 演算法**
**優勢**：
- 自動維護 Pareto 最優解集
- 提供多個不同風險/報酬特性的策略供選擇
- 比單目標優化更穩健

#### 3. **並行計算加速**
```python
# v8.2: 序列評估
for individual in population:
    fitness = evaluate(individual)  # 慢

# v9.0: 並行評估
with Pool(processes=8) as pool:
    fitnesses = pool.map(evaluate, population)  # 快 8 倍
```

**效果**：
- 在 Colab Pro+ 上使用 8 核心
- 評估速度提升 **5-8 倍**
- 相同時間內可演化更多世代

#### 4. **智能參數範圍**
```python
# v8.2: 粗糙範圍
gene.append(random.uniform(-50, 100))  # 可能產生不合理參數

# v9.0: 智能限制
def clip(val, min_val, max_val):
    return max(min_val, min(max_val, val))

pe_min = clip(gene[12], 5, 15)    # PE 範圍合理化
top_n = positive_int(gene[14], 3, 30)  # 確保正整數
```

**效果**：
- 減少無效個體
- 加快收斂速度
- 提升策略穩健性

#### 5. **自適應變異率**
```python
# 前期：探索
adaptive_mutation_rate = 0.25  # 高變異

# 後期：精煉
adaptive_mutation_rate = 0.125  # 低變異
```

**效果**：
- 前期快速探索
- 後期穩定收斂
- 避免震盪

## ❓ 常見問題

### Q1: 程式跑很久都沒達標怎麼辦？

**A:** 這是正常的。基因演算法是啟發式搜索，不保證一定找到達標解。建議：

1. **降低目標**：
```python
TARGET_SHARPE = 3.5          # 從 4.0 降到 3.5
MIN_CAPACITY = 3_000_000     # 從 500萬 降到 300萬
```

2. **增加演化代數**：
```python
num_generations = 1000  # 讓演算法跑更久
```

3. **多視窗並行**：同時開 4 個視窗，增加找到達標解的機率

### Q2: 胃納量一直不足怎麼辦？

**A:** 提高胃納量權重：

```python
MULTI_OBJECTIVE_CONFIG = {
    'sharpe_weight': 0.4,        # 降低
    'capacity_weight': 0.4,      # 提高到 40%
    'return_weight': 0.15,
    'drawdown_weight': 0.05,
}
```

### Q3: 記憶體不足錯誤？

**A:**
1. 確保使用 Colab Pro+ 的 High-RAM 模式
2. 減少族群大小：
```python
'population_size': 60,  # 從 80 降到 60
```

### Q4: 如何解讀「綜合適應度」？

**A:**
- **< 5.0**: 表現差，遠未達標
- **5.0 - 7.0**: 中等，可能部分達標
- **7.0 - 9.0**: 良好，有機會達標
- **> 9.0**: 優秀，很可能達標

綜合適應度 = 各指標加權分數總和（滿分約 10 分）

### Q5: 找到的策略會過擬合嗎？

**A:** v9.0 已內建防過擬合機制：

1. **樣本內/外驗證**：會自動分割數據測試
2. **多個達標解**：提供 Pareto 前緣供選擇，不只一個解
3. **硬約束**：胃納量和回撤限制確保實用性

**建議**：
- 選擇「綜合適應度」穩定的解（不是最高的）
- 對最終策略進行紙上交易驗證

## 🔧 技術細節

### 適應度計算公式

```python
# 夏普值分數（滿分 5 分）
if sharpe >= 4.0:
    sharpe_score = 5.0 + (sharpe - 4.0) * 0.5
else:
    sharpe_score = (sharpe / 4.0) * 5.0

# 胃納量分數（滿分 5 分）
if capacity >= 500萬:
    capacity_score = 3.0 + min(2.0, (capacity - 500萬) / 1000萬)
else:
    capacity_score = (capacity / 500萬) * 3.0

# 綜合適應度
fitness = (
    sharpe_score * 0.5 +
    capacity_score * 0.3 +
    return_score * 0.15 +
    drawdown_score * 0.05
)

# 硬約束懲罰
if capacity < 250萬: fitness *= 0.3
if drawdown > 30%: fitness *= 0.5
```

### 並行計算實現

```python
class ParallelEvaluator:
    def __init__(self, num_workers=8):
        self.pool = Pool(processes=num_workers)

    def evaluate_population(self, population):
        # 並行評估
        fitnesses = self.pool.map(evaluate_individual, population)
        return fitnesses
```
